# Memory

A memory that is no longer true is deleted. Not marked, not annotated, not
superseded in place.

## Wrong memories are removed, not flagged

Marking a memory invalid leaves it loaded. It still costs context, and it now
carries a fact plus a correction that has to be reconciled every time it is read
— two things to hold instead of none.

When a memory turns out to be wrong, delete the file.

When the underlying fact changed, edit the existing memory to say the new fact.
Never add a second memory recording that the first one is out of date.

Deleting a memory also removes its line from the index. A pointer to a file that
is gone is worse than either.

## Memory is a working set, not a log

Entries leave. A store that only grows is one nobody reads.

Thirty memories on one project is not thirty useful facts. It is a few facts and
a pile of tombstones.

## Do not save what will go stale

Before saving, ask whether it will still be true in a month.

- Counts, current state, and progress are stale immediately
  (`stop-counting.md`).
- Anything the repository already records — structure, history, configuration —
  needs no memory. Read it instead.

Save what is durable: how the user works, what they have decided, and why
something is the way it is.
